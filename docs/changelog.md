## 2026-11-09 · 插件 0.36.0 · 角色分端第三批：企业管理员与咨询师端、按钮层级

按《角色分端定稿方案》第三、四、六部分和《产品走查》拍板的 5 条。

- **咨询师不定版、不重开**：`reopen` 只允许企业项目负责人（咨询管理员可代为处理）；咨询师端不再出现灰色的“本步完成 / 确认定版 / 解锁重开”按钮，轮到企业时只写一句“等企业…”，已定版的表什么都不显示。退回修改保留。
- **企业管理员总览**：成员还没到位时第一张卡是「邀请成员」（直达本企业 › 邀请注册），然后「上传资料」，再是“现在做这张表”；一页只有一个实心按钮，到位后自动退后。
- **资料页「成员上传的材料」**：成员填表时传的附件列在资料库下面，企业管理员 / 咨询师挑有用的「加入资料库」，加入后数字咨询师才检索得到。`dingze:listAttachments` 不带表号时返回整个项目的附件。
- **保存改为自动保存**：停笔 2.5 秒后写一版，不弹提示，顶部状态字写“已保存 时间 · v 版本”或“N 处未保存 · 稍后自动保存”；Ctrl / ⌘ + S 仍可立刻保存并弹提示。预览修改建议、看旧版本、服务端有新版本时不自动保存。
- **每页一个实心主按钮**：流程区次要动作（退回 / 撤回）改为文字按钮。
- **中栏与右栏联动**：修改卡的每一条点一下滚到表里那一行；光标在表里某一行时，碰到这一行的修改卡加一圈高亮，那一条标“当前行”。
- **专家咨询只有一个入口**：顶栏不再放「专家咨询」页签，总览也没有链接，数字咨询师面板底部「找真人咨询师」直达。
- 注意：角色规则在插件 `shared` 里，门户和插件要一起发布。`docs/user-guide.md` 的角色表同步。

## 2026-11-09 · 插件 0.35.0 · 角色分端第一批：登录页与普通员工端

按《角色分端定稿方案》第一、二部分做：企业与咨询师分开登录，普通员工只看到“填哪张表、怎么填、保存”。

- **登录页分两个身份**：「企业」页签带“免费试用”和“有邀请码？申请加入”；「咨询师」页签只登录。页签选择记在本机。
- **只有一个项目就直接进总览**，不再先看项目列表。
- **普通员工（部门负责人、成员）端**：顶栏没有「资料」；总览第一张卡就是“现在填哪张表”，没有上传 / 邀请 / 项目启动卡；填表页只剩「保存」，“这步做完了 / 提交复核 / 定版”等流转按钮不渲染；右栏没有「修改」页签；首次进项目弹三步指引（看任务 → 填表 → 保存后告诉负责人）。
- **服务端同步收紧**：`stepDone` 只允许企业项目负责人；`submitReview` 允许企业项目负责人和咨询师；资料库上传 / 删除和企业画像编辑只允许企业项目负责人、咨询师、咨询管理员（`canManageLibrary`）。普通员工保存草稿不受影响。
- **表下附件**：填表页新增「附件」区和对话里“上传附件填这张表”。Word / PDF / Excel / 文本在浏览器里抽文字，图片和扫描件 PDF 转成图片交给多模态模型识图（最多 8 页）；数字咨询师出修改卡，逐项确认后才写进表。附件挂在这张表下（`dz_materials.kind = attachment`，`artifactCode`，`inLibrary = false`），不进资料库，不参与资料检索；企业项目负责人 / 咨询师可以“加入资料库”。新增接口 `dingze:listAttachments`、`dingze:setMaterialLibrary`。
- 注意：角色规则在插件 `shared` 里，门户和插件要一起发布。已有 `dz_materials` 记录的 `inLibrary` 默认 true，不用迁移。

## 2026-11-09 · 门户 · 产品走查第一批：工作区

逐页走查后按“少即是多”整改填表页（方案见《产品走查：问题清单与整改方案》）。

- **顶部从三行并成两行**：第一行位置与状态，第二行表名、撤销 / 重做、「书中方法」、「更多」和流程按钮。修订开关、批注、圈选、历史、导出、看示例、快捷键都收进「更多」，各只有一个入口；导出改为弹层。只有导图 / 树形表才有第三行结构工具条。
- **「怎么填」并入右栏「书中方法」**：编辑器的填写提示显示在书中方法顶部，顶栏和底部状态条不再各放一个入口。
- **顶栏未开启的阶段不可点**（之前点进去是一张锁定页）；「成果」的序号按阶段数计算。
- **上游改了什么**：每条改动旁标出“本表 N 行引用了它”，点一下关掉弹层、滚到那一行。
- **表格行快捷键**：光标在行内时 Alt+Shift+↑ / ↓ 上移下移，Alt+Shift+Backspace 删除（可撤销），和树形表一致；快捷键面板同步。
- **统一确认弹层**：撤销已保存修改、离开未保存的表、“不需要重开”说明都用站内弹层，不再用浏览器原生 confirm / prompt；删带下级的节点不再先问，删后提示里直接“撤销”。
- 删掉没有引用的旧左栏组件 `step-bar.tsx`。

## 2026-11-02 · 插件 0.33.0 · 试用版改为客户全流程

甲方反馈：试用版应该是客户从接触网站到完成任务的完整流程，两家演示企业只是案例；手册要简洁。

- **首页和免费试用**：没登录时打开网站先到首页（五步流程、免费试用、登录）。「免费试用」填企业名称、姓名、手机号、密码，勾选试用说明，就开好试用企业、企业管理员账号（手机号登录）和一个自助项目，自动登录进第 1 步“上传资料”。
  - 新接口 `dingze:trialSignUp`（公开，按 IP 每小时 5 个、全站每天 200 个，带蜜罐字段）；`dz_enterprises` 加 `trial`；运营和咨询管理员自动加入新企业空间，并收到站内通知。
  - 登录页加“还没有账号？免费试用”。邀请码申请照旧保留。
- **项目里按流程走**：顶栏改为 总览 · ① 资料 · ② 战略解码 · ③ 目标分解 · ④ 计划制定 · ⑤ 成果，做完的打勾、没开启的带锁；三个阶段各跳到本阶段第一张没定版的表。原“待办”改为“总览”，最上面是五步流程条和下一步按钮；资料没准备、也还没开始填表时，第一个按钮是“上传资料”。
- **阶段名**：界面上用 战略解码 / 目标分解 / 计划制定，书里的“定战略责 / 定目标责 / 定行动责”作小字保留。导出、计划书和数字咨询师的用语不变。
- **示例项目**：左侧菜单「示例项目」只读展示虚构企业瀚川燃气 2026 的全套表（取自演示数据种子）；每张表的工具栏有「看示例」，新窗口打开同一张表对照着填。演示企业的账号和数据不变。
- **批量进人**（第二轮反馈）：邀请码加「免审核」（默认开），凭码注册马上开通并进项目，注册页直接登录；训练营批次页「一键发团队码」给每家企业一个免审核码（项目成员 · 20 人 · 60 天），可复制全部转给企业；新接口 `dingze:campInvites`，`dz_invites.autoApprove`。
- **上传资料放到最前**（第二轮反馈）：资料页页签改为 ① 上传资料 · ② 企业画像 · ③ 组织与职责，默认打开上传；没有资料时整块是一个大的上传按钮。
- **空表起草**（第二轮反馈）：新表打开时顶部提示「按资料起草这张表」，一键让数字咨询师出整张表的修改卡；旁边是「看示例」。
- **首次指引**：企业侧第一次进新项目弹四步操作指引（上传资料 → 战略解码 → 目标分解 → 计划制定，一步一页），关掉后本机不再弹；总览“看操作指引”随时重开。
- **手册**：新增客户版[三分钟上手](quick-start.md)（门户左侧「使用指南」同一份）和我方版[运营与咨询师速查](ops-quick-ref.md)；原操作手册改名“详细参考”，只作查阅。
- 注意：
  - 开放公开注册前要在 dev 上把注册 → 上传资料 → 第一张表走通一遍（多空间插件在未登录请求下建空间和账号的行为需实测）。
  - 准生产上如果开着密码策略，试用注册的密码规则要和它一致（现在是至少 8 位、字母加数字）。
