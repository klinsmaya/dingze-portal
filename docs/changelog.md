# 更新记录

「自驱战略 · 定三责」门户 `dingze` 与服务端插件 `@ziqu/plugin-dingze` 的更新记录，新的在上。

- 每一节标出当时的插件版本。只改了门户的提交不升插件版本，写作“门户”。
- 门户每次都用 `nb portal deploy dingze` 发布；插件按 `docs/deploy.md` 发布。
- 标“注意”的条目需要运维、咨询师或企业用户知道。
- 逐条验证证据见[验收记录](acceptance.md)，后续计划见[路线图](roadmap.md)。

## 2026-10-15

### 插件 0.27.0 · 开营前 UX 改版第 1 批

依据《定责门户 · 开营前 UX 改版清单》（2026-10-15）。

- **企业项目负责人可以自己解锁重开（F4 / F5，按甲方意见简化）**：
  - 陪跑项目里，企业项目负责人在已定版的表上直接点“解锁重开”，必须写原因；全体项目成员（含咨询师）收到通知，原因写在通知里。
  - 重新定版仍要提交复核、复核通过、确认定版，定版门禁不变。
  - “上游已变更”“组织已变更”也可以由企业项目负责人判断（解锁重开，或“不需要重开”并写理由）。
- **显示设置（T1 / T2）**：
  - 顶栏“显示”菜单合并白天 / 黑夜 / 自动和字号小 / 中 / 大，整站按比例缩放。
  - 头像菜单里的“显示设置”和新的 `/settings` 页是同一份设置，存在本机，换项目、下次登录都保留。
- **头像菜单（T4）**：增加“显示设置（主题与字号）”“快捷键与帮助”。
- **顶栏（T3）**：
  - 第一行改为企业和项目名，第二行是阶段和当前步骤。
  - 子步骤多于 4 个时（如六分法），窗口不够宽就收进“本表小节”下拉，不再和右侧按钮挤在一行。
- **左栏状态与表头一致（F8）**：一步里的必做表都定版、可选表没动过时，左栏写“已定版”（修掉 S1-06 左栏“进行中”、表头“已定版”的不一致）。
- **只读视觉（F7）**：已定版或只读时，下拉框不再显示禁用态的灰框和箭头，输入框去掉边框，看起来就是文字。
- **书中方法入口**：
  - 底部状态条加“书中方法”，点开右栏对应页签。
  - 战略屋下面原来展开的“书中方法 · 战略屋怎么填”改成打开右栏的链接，三条要点并入 S1-01 的书中要点。
- 注意：陪跑项目的企业项目负责人现在会在已定版的表上看到“解锁重开”按钮；操作手册和演示账号说明已同步。

### 插件 0.26.0 · 甲方“书中方法”复核意见

- **书中方法面板改为六块。** 六块是：本步目的、准备、怎么做、示例与反例、完成检查、来源与下一步。
  - 首屏只显示目的、怎么做、完成检查，其余点开再看。
  - S2-01 跟随当前子步骤切换（股东价值差距 / 客户价值主张 / 关键流程 / 战略资产），S2-03 跟随“定目标 / 找路径”分区切换。
  - 每条内容标出处：【书】【平台】【建议】，未签认的用语标【待确认】。
- **改掉与需求冲突的说法。**
  - S1-04 是选做；S1-05“不超过 6 个”是建议；S1-07 的 70% 是参考；S2-06 的岗位层级可选；S2-08 的二八原则是启发。
  - 三不做指不投入、不介入、不承担。
  - 年度经营计划质询会在线下开，平台不设门禁。
- **执行摘要改为同源。** 计划书第一章按定版成果自动汇总。
  - 公司级写使命愿景、本年度战略 KPI 目标、公司级年度目标、关键项目，以及资源缺口和其中的重大缺口；项目预算单位一致时给出合计。
  - 部门级写承接项（分主责、协同）、计分卡指标数、牵头项目和资源缺口。
  - 原“执行摘要”录入框改为选填的“补充说明”，不再是定版必填项。
- **口径同步。**
  - 对话起步卡上的“定版门禁”改为“完成检查”。
  - 自查复核清单改用完成检查，S2-01 / S2-03 包含各子步骤和分区的检查。
  - 数字咨询师的计划书和找路径方法写明：执行摘要同源、质询线下、三不做口径，以及“经营模式 / 老客户转介绍”与书中“新层次 / 忠诚度”的对应待确认。
- 注意：
  - 自助项目里已经在做自查复核的表，原来的勾选答复对不上新清单，需要重新勾一遍。
  - 已定版的计划书再打开或导出时，第一章按新方式汇总，数字来自定版时引用的上游版本。

### 插件 0.25.0 · 预验收意见中不需甲方拍板的优化

- 确认定版弹窗列出：
  - 与上一定版的差异；
  - 未处理的校验建议和未解决批注；
  - 定版后以它为依据的下游表；
  - 重开人：按服务方式写主咨询师或企业项目负责人。
- 等待说明写清等谁、从何时开始，例如“等主咨询师复核（张总 10-11 提交）”。
- 左右栏的收起状态在本机记住，换表不变。
- 计划书和任务书 Word 增加目录、页眉、页脚页码（第 X 页 / 共 Y 页）。
- 合计推不回目标时写明“还差 N / 多 N”。
- 任务书、推进表、资源表增加专业检查：
  - 不可验收的说法；
  - 节点晚于任务书结束时间；
  - 验证排在投产之后；
  - 缺口 ≠ 需求 − 存量。
- 找路径方法补充分支式引导和贡献核算。
- 三位数字咨询师的开场白不再固定讲找路径。
- 版本对比显示行名和字段名，不再出现技术键和 JSON。

- S3-02 项目任务书可以单独导出 Word。
- 只有指标和单位都相同才求和；口径不同时显示“共同支撑，不求和”。
- 路线中的一步含多张表时，链接到第一张已解锁的表。可选表（P1）不标红“必须改”。

### 插件 0.23.0 · 预验收整改第一批

### 插件 0.22.2 · 邀请码注册（审核制）

- 运营或企业管理员发邀请码，码上可以绑定企业，以及可选的项目、角色、部门、名额和有效期。
- 申请人在 `/register` 用邀请码提交申请，审核通过后才建账号。
- 登录前会查申请状态，提示“审核中”或“未通过”的原因。
- 注意：公开接口按 IP 和邀请码限流，限流计数存在进程内，多实例部署时要改成共享存储。

### 插件 0.21.0 · 训练营批次

- 运营侧新增训练营批次，分三页：营前准备（导入企业和账号、检查是否就绪）、现场看板（按今日目标表看进度、提醒）、结营。
- 结营时为每个项目选择服务方式，可以导出结营小结。

### 插件 0.20.0 · 服务方式：陪跑 / 自助

### 插件 0.18.0 – 0.18.2 · 统一编辑与易用性

- 所有可编辑表使用同一套编辑交互：
  - 修改日志可以逐条撤销 / 重做；

  - 企业端导航收敛；

- 交接说明 `HANDOFF.md` 和演示数据种子脚本入库。脚本的凭据从环境变量和私有目录读取，不进仓库。
