**项目**：企业战略咨询平台「自驱战略 · 定三责」V1

**测试环境**：https://ziqu-dev.aihupo.cn/x/dingze/ （NocoBase 2.4.0-alpha.9，插件 `@ziqu/plugin-dingze` 0.26.0）

## 1. 做了什么

把书中“定三责”的三张管理检查表变成在线的逐表工作流：每一步一张成果表，企业填写 → 本步完成 → 咨询师复核 → 企业确认 → 定版；下游引用上游的定版内容，上游一改下游提示“上游已变更”。数字咨询师随阶段陪跑，建议经用户确认后才写入成果。

| 模块 | 内容 |
|---|---|
| 定战略责 | S1-01 六分法 / 战略屋（含使命五要素、愿景三法底稿）、S1-02 战略地图、S1-03 逻辑表、S1-04 IPOOC、S1-05 KPI 筛选、S1-06 战略 KPI 表、S1-07 年度分解 |
| 定目标责 | S2-03 公司级目标路径系统表（第一步定目标区，含预算底稿；第二步找路径，思维导图 / 表格 / 表 3-10 / 表 3-9）、S2-01 解码地图（找路径子步骤 1–4）、S2-08 关键项目、S2-04 RACI（含表 3-18 验证）、S2-05 部门承接、S2-06 部门路径、S2-07 计分卡 |
| 定行动责 | S3-02 任务书（含项目化判定、WBS）、S3-05 推进表（含节点表）、S3-06 资源匹配、S3-07 / S3-08 公司 / 部门年度经营计划书（八章，同源章节自动汇总，Word 导出） |
| 流程 | 状态机（保存 / 本步完成 / 提交复核 / 复核通过 / 退回 / 确认定版 / 解锁重开 / 强制定版 / 强制退回 / 开例外）、阶段门禁、硬校验、上游变更传播、版本快照、审计、团队异议 |
| 数字咨询师 | 三位阶段咨询师（定战略责 / 定目标责 / 定行动责），读当前成果，出修改建议卡，用户确认后写入；每张表的“书中方法”（本步目的、怎么做、完成检查，展开看准备、示例与反例、书中要点、来源；S2-01 / S2-03 按子步骤和分区切换） |
| 成果与交付 | 成果管理页（状态、版本、操作者、AI 初稿与定版差异、版本对比、导出清单）、交付页（定版交付物、各部门计分卡、导出记录）、Excel / Word 导出（未定版标草稿） |
| 通知 | 站内通知（待复核、待确认、退回、定版、重开、上游已变更、加入项目），可选邮件通道 |
| 运营管理 | 企业开通（建空间 + 企业管理员账号）、停用、成员与部门、咨询团队账号、项目新建与分派、方法与规则包（只读） |
| 咨询师工作台 | 跨企业汇总待复核、待提交复核、待企业确认、上游已变更、待跟进 |
| 统一编辑交互（设计稿 10） | 所有可编辑表同一套：直接改即时生效、逐条撤销 / 重做；调结构（下级 / 同级、升降级、上下移、移动到…带预览、拆分、合并、删除 8 秒可撤销，思维导图可拖动）；批注钉在格子 / 节点（编号 ①②③、圈选一组、回复、@、按批注修改）；对话只出修改卡（原值 → 新值 → 影响，确认才写入，AI 不直接改人写的内容）；修订对比任意版本；右栏数字咨询师 / 批注 / 修改三页签；底部状态条与 ? 快捷键面板；校验问题点击定位 |
| 易用性 | 项目卡片与“待办”给出具体下一步；项目入口两端统一为待办 / 定责 / 资料 / 成果；表名人话优先、书号小字；协作状态（顾问在审 / 已退回 / 待你定版）；首次“本步完成”说明；登录页忘记密码、无权限页回我的项目；导出页 Word 为主按钮 |
| 资料与画像 | 资料库（上传原件并提取文字，Word / PDF / Excel / 文本，可下载原件）、企业画像（事实 / 假设 / 未知 / 待补，复核与确认），数字咨询师检索资料并注明出处 |
| 运营看板 | 项目阶段进度、待办积压、数字咨询师用量（只记录不计费） |
| 引导缺口 | 咨询师记录，运营 / 咨询管理员评审（采纳 / 不采纳 / 已发布），通知记录人 |
| 专家咨询 | 申请（授权引用定版成果）→ 受理分派 → 预约 → 纪要与意见 → 关闭 / 撤回 |
| 图形导出 | 战略屋 / 六分法、战略地图导出 PNG / SVG；公司级计划书 Word 第一章附图 |
| 安全与隔离 | 一企业一空间；项目、成果、通知、导出、批注、资料、画像、专家咨询互不可见；公开自助注册已关闭 |

## 3. 验收结论

规格 5.2 的 8 条总体标准和 5.3 的核心成果专项要求逐条对应见[验收记录](acceptance.md)。摘要：

- 核心闭环实证（5.2 第 7 条）：在第二家测试企业用数字咨询师起草定战略责 5 张 P0 表，每张各有 AI 初稿版和人工版，走完复核确认定版，定目标责自动解锁，重开上游后下游出现“上游已变更”。无模型调用错误。
- 跨企业隔离（5.6 第 4 条）：另一家企业的账号对项目、成果、历史、版本对比、交付、导出、通知、底层数据表均不可访问；有自动化用例。
- 第一家测试企业已走完三阶段全部 18 张 P0 表的定版与导出。
- M5 七项功能逐项用接口与浏览器验证，见[验收记录](acceptance.md)末节。
- `npx vitest run tests/logic tests/components` 223 项通过（另有 2 个 Registry 测试文件用的是 `node:test`，vitest 不加载，与本项目无关）；隔离 E2E 2 项通过；类型检查、lint、生产构建（门户发布）通过。

## 6. 已知限制

- 定版后的下拉框仍显示为禁用的下拉，文本格已改为纯文本。
- 推进表“状态”“前置节点”等列在窄屏需要横向滚动。
- 扫描版 PDF 无文字层时提取为空，需粘贴文字（原件仍保存，可下载）。
- S2-01 解码地图与 S2-03 路径仍是两份数据，靠“子步骤 5 导入”衔接；设计稿提出的“一棵路径树”需架构确认后再合并。
- 修改记录在本机未保存前只存在浏览器里，保存时随版本存档；离开页面前有未保存提醒。
- 用量按对话所属项目统计，不在项目页面里发起的对话不计入；Token 为模型返回值，仅供参考。
- 专家只能从企业空间里已有的咨询师中分派；外部专家需先建咨询师账号并加入该企业。
- 登录 E2E 用例已改为中文标签，但本次开发环境的浏览器版本与 Playwright 不匹配，未能运行；隔离 E2E 已运行通过。
